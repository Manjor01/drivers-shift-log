# Дневник смен водителя

Небольшое веб-приложение: FastAPI + SQLite, React + TypeScript. Показывает поездки и доход за выбранный день, принимает новые поездки и защищает от дублей.

## Запуск через Docker Compose

Нужен Docker с Compose v2:

```bash
docker compose up --build
```

- Клиент: http://localhost:8080
- Документация API: http://localhost:8000/docs
- В интерфейсе выбран **1 октября 2026 года**, чтобы сразу показать две поездки из задания.
- Исходные поездки загружаются из `data/seed.json` при запуске. Повторный запуск не создаёт дублей.
- SQLite хранится в томе `trips-data` и переживает остановку контейнеров.

Остановка: `docker compose down`. Для полного сброса данных: `docker compose down -v` (удаляет сохранённые поездки).

## Локальный запуск

Нужны Python 3.12+, Node.js 22.13+ и npm. Все команды выполняются из корня проекта.

```bash
python -m venv server/.venv
# Linux/macOS:
source server/.venv/bin/activate
# Windows PowerShell:
# .\server\.venv\Scripts\Activate.ps1
python -m pip install -e "server[dev]"
python -m uvicorn app.main:app --reload --port 8000
```

В другом терминале:

```bash
cd client
npm ci
npm run dev
```

Клиент доступен на http://localhost:5173. Vite проксирует `/api` на сервер :8000; CORS-настройки не нужны. В production запросы проксирует nginx.

### Настройки сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_TZ` | `Asia/Almaty` | Часовой пояс дня и возвращаемого времени |
| `DB_PATH` | `data/trips.db` | Путь SQLite относительно текущего каталога |
| `SEED_PATH` | `data/seed.json` | Путь исходного JSON; отсутствующий файл допускается |

Сервер запускайте из корня проекта: так он найдёт пример JSON. Невалидный seed или конфликт ID останавливает запуск, чтобы не скрывать ошибки данных.

## Что сделано

- Сводка: число поездок, выручка, комиссия, на руки; отдельные показатели для cash/card.
- Список поездок, выбор даты и переключение соседних дней.
- Состояния загрузки, пустого дня и ошибки с повторной попыткой; адаптивная вёрстка.
- Добавление через API и дополнительную форму клиента.
- Строгая валидация, UTC-нормализация времени, хранение SQLite.
- Защита от повторов на уровне PRIMARY KEY и атомарного INSERT.
- Тесты домена, сводки, границ дней, API, конкурентных повторов и клиента.
- Docker Compose и GitHub Actions для проверок и сборки.

## API

### `GET /api/day?day=2026-10-01`

Возвращает список и сводку одним запросом:

```json
{
  "day": "2026-10-01",
  "timezone": "Asia/Almaty",
  "summary": {
    "total": {"trip_count": 2, "revenue": 3900, "commission": 585, "net": 3315},
    "cash": {"trip_count": 1, "revenue": 1500, "commission": 225, "net": 1275},
    "card": {"trip_count": 1, "revenue": 2400, "commission": 360, "net": 2040}
  },
  "trips": [
    {"id": "t1", "start": "2026-10-01T08:10:00+05:00", "end": "2026-10-01T08:32:00+05:00", "amount": 2400, "payment": "card", "commission": 360},
    {"id": "t2", "start": "2026-10-01T09:05:00+05:00", "end": "2026-10-01T09:20:00+05:00", "amount": 1500, "payment": "cash", "commission": 225}
  ]
}
```

Пустой день: HTTP 200, нулевая сводка и `trips: []`. Некорректная дата: 422. Список отсортирован по времени начала, затем ID.

### `POST /api/trips`

```bash
curl -i http://localhost:8000/api/trips \
  -H 'Content-Type: application/json' \
  -d '{"id":"t3","start":"2026-10-01T10:00:00+05:00","end":"2026-10-01T10:25:00+05:00","amount":2000,"payment":"cash","commission":300}'
```

| Код | Поведение |
|---|---|
| 201 | Новая поездка сохранена |
| 200 | Тот же ID и те же нормализованные данные; повтор без дубля |
| 409 | ID уже существует, но данные отличаются; запись не меняется |
| 422 | Ошибка валидации с указанием поля |

Времена одного момента с разными UTC-офсетами считаются одинаковыми. Повторяйте запрос с тем же ID: новый ID обозначает другую поездку.

## Правила и допущения

- День определяется по началу поездки в `APP_TZ`; интервал от полуночи включительно до следующей полуночи исключительно. Поездка через полночь целиком относится к дню начала.
- `net = revenue - commission` одинаково для наличных и карты. Это доход после комиссии, без отдельного учёта задолженности платформе.
- Деньги — целые KZT. `float`, строковые числа и `bool` не принимаются. `amount > 0`, `0 <= commission <= amount`.
- Требуется время с часовым поясом и `end > start`. Внутри всё нормализуется в UTC. Максимальной длительности поездки нет.
- Дополнительные согласованные ограничения: `amount <= 1_000_000_000`, ID из 1–64 символов `[A-Za-z0-9._:-]`, запрет лишних полей. Эти ограничения не являются требованиями исходного задания.
- Один водитель, без авторизации и проверки пересечений поездок. Продакшен-платёжный учёт вне объёма мини-проекта.

## Использование ИИ

Claude помог с планом, инфраструктурой и тестами домена. После исчерпания лимита продолжение выполнено с Codex: восстановление недостающей модели из тестов, сводка, SQLite, API, клиент и проверки. Решения задавались заранее; код проверялся тестами и инструментами.

Реальный пример ошибки: AI предложил ограничить поездку 24 часами, хотя задания такого правила не содержит. После ревью ограничение убрано и добавлен тест на многодневную поездку. Подробности: [docs/AI_USAGE.md](docs/AI_USAGE.md), [docs/DECISIONS.md](docs/DECISIONS.md).
